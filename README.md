# Модернизация компонента «Умный дом»: Модуль Radio (Flexible Версия)

Учебный проект, развивающий логику модуля управления радиостанциями. Основной фокус данной версии — переход от фиксированных значений к гибкой настройке объектов через **перегрузку конструкторов (Constructor Overloading)**. Также в проекте отрабаываются навыки командной разработки: работа в изолированных Git-ветках и верификация кода через **Pull Request (PR)**.

## 🎯 Новые цели и задачи проекта
* **Использование конструкторов**: реализация конструктора по умолчанию (для создания радио на 10 станций) и конструктора с параметром (для кастомного количества станций).
* **Динамическая бизнес-логика**: перенос граничных условий переключения станций с жестких констант (`0-9`) на динамический расчет на основе размера массива станций.
* **Работа с ветками в Git**: создание изолированной ветки `flexible`, ведение разработки в ней и создание Pull Request для интеграции кода.
* **Тестирование Pull Request**: настройка CI (GitHub Actions) для автоматического прогона тестов при создании и обновлении PR.

## 📻 Модернизированная бизнес-логика модуля Radio

Объект `Radio` по-прежнему инкапсулирует в себе *номер текущей радиостанции* и *уровень громкости звука*, но теперь также хранит *количество доступных станций*.

### 1. Работа с радиостанциями (Гибкий диапазон)
* **Конструктор по умолчанию**: если количество станций не указано пользователем, автоматически создается радио на **10 станций** (доступные индексы: от `0` до `9`).
* **Конструктор с параметром**: позволяет задать любое количество радиостанций при создании объекта (например, если передано `30`, то доступные индексы будут от `0` до `29`).
* **Кнопка `next`**: переключает на следующую станцию. 
  * *Граничное условие*: если текущая станция является максимальной (например, `29` при количестве станций `30`), то при нажатии `next` радио переключается на `0`.
* **Кнопка `prev`**: переключает на предыдущую станцию.
  * *Граничное условие*: если текущая станция `0`, то при нажатии `prev` радио переключается на максимальную доступную (например, `29`).
* **Сеттер**: позволяет напрямую выставлять номер станции с валидацией границ текущего объекта.

### 2. Работа с уровнем громкости (Диапазон: 0–100 — без изменений)
* **Кнопка `+`**: увеличивает громкость на 1. При достижении `100` значение фиксируется.
* **Кнопка `-`**: уменьшает громкость на 1. При достижении `0` значение фиксируется.

## 🧪 Обновленный тест-дизайн и покрытие (JaCoCo)

В связи с изменением архитектуры класса был проведен повторный тест-дизайн. В класс `RadioTest` добавлены новые тест-кейсы, проверяющие поведение как дефолтного объекта радио, так и кастомного (с разным количеством станций). 

Пакет автотестов проверяет:
* Создание объектов через оба конструктора.
* Граничные переходы (`next`/`prev`) для кастомного количества станций.
* Невалидные значения в сеттере для кастомных границ.

Локальный запуск тестов и сборка по-прежнему выполняются командой:
```bash
mvn clean verify
```
Достигнуто **100% покрытие веток кода (Branch Coverage)** по счетчику JaCoCo.

## 🚀 Процесс интеграции и CI
1. Вся разработка велась в отдельной ветке `flexible`.
2. Изменения отправлены на GitHub, где открыт **Pull Request**.
3. Настроенный конвейер **GitHub Actions** автоматически запустил сборку `mvn clean verify` непосредственно на пулл-реквесте.
4. Все тесты успешно прошли, подтверждая стабильность новой логики (зеленый статус сборки).
